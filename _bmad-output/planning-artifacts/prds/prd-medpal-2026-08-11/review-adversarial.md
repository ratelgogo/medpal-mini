# Adversarial Review — 可信的就医陪伴服务平台

## Gate verdict

拒绝按当前草案进入上线设计或开发。它能够说明“理想订单如何走完”，但没有证明患者在异常情况下会安全、可追责地被照护，也没有证明平台能正确处理敏感数据、退款、扣款和人工运营动作。

## Findings

- **[critical] 患者安全与医疗行为边界缺失**（prd.md:34-40、48-58）— 陪诊师可能在就医现场接触患者、就诊码、病历或医生信息，但文档没有禁止诊断/治疗/代签、没有急症升级、失联和事故处置。Fix：定义服务边界、紧急联系人/医院升级、拒绝服务和事故上报；未完成前不得作为可上线能力。
- **[critical] 4 位就诊码的安全模型不成立**（prd.md:34-35；addendum.md:19）— 没有说明码由谁生成、有效期、尝试次数、绑定对象、泄露/遗失/代操作、重放和审计。四位空间很小，不能仅凭输入成功证明本人授权。Fix：定义强绑定和一次性/短时凭证策略，限制尝试、脱敏展示、撤销与人工核验，并记录每次验证证据。
- **[high] 敏感数据处理完全未落地**（prd.md:36；addendum.md:11、18）— 定位、照片、可能的病历/处方/检查信息属于高敏感过程记录，但无收集目的、授权主体、最小权限、查看范围、加密、留存、删除、导出、第三方/陪诊师可见范围和审计。Fix：增加数据分类与生命周期要求，分别约束家属、患者、陪诊师、运营和售后人员权限。
- **[high] 服务结束无需家属确认会制造不可逆争议**（prd.md:37-40、44-46）— 陪诊师单方点击结束即可完成订单，平台缺少到场、服务内容、时长、异常和家属可申诉的证据门槛。Fix：保留该决策也必须定义结束凭证、可争议窗口、自动通知、证据冻结和售后反向更正规则。
- **[high] 退款、优惠券、佣金和押金缺少账务不变量**（prd.md:32-33、50-58、62-76）— 同一取消原因存在退款/券/扣款/降佣组合，但没有金额、税费、原路退款失败、重复执行、部分退款和账户余额的规则。Fix：建立订单金额、用户退款、优惠券、平台佣金、陪诊师收入和押金的账务模型，所有人工动作幂等且可审计。
- **[high] 订单状态和并发条件未定义**（prd.md:28-40、62-76）— 自动取消、人工指派、陪诊师拒绝、超时、服务开始和结束可能同时发生，文档没有状态机、锁定规则、事件顺序或重试行为。Fix：列出状态、合法转换、触发者、互斥条件、超时、通知和补偿事务。
- **[high] 扣押金缺乏证据、申诉与公平性机制**（prd.md:50-58、71-78）— 首期不开放陪诊师申诉，20% 暂定且押金不足规则未定；平台可以单方面定责和扣款，极易产生纠纷与供给流失。Fix：定义责任认定证据、人工复核、申诉/复议时限、扣款上限、押金不足处理和审计日志；“暂不开放申诉”应作为明确风险接受决策而非默认实现。
- **[high] 没有真正的异常旅程**（prd.md:42、48-78）— 目前异常主要是“无人接单/取消/售后”，未覆盖患者迟到或无法就诊、陪诊师到院找不到人、医院临时改期、支付成功但订单未建、通知未送达、患者拒绝提供码、服务中断和紧急医疗事件。Fix：为患者/家属、陪诊师、运营分别补一条异常旅程，并为每个分支给出责任人和用户可见结果。
- **[medium] 人工运营动作没有最小权限和双人复核**（prd.md:62-69、54-58）— 运营可降佣、发券、退款、扣款、安抚，但没有角色权限、理由、审批、撤销和审计要求。Fix：按财务/处罚风险分级授权，敏感动作要求理由和复核，所有动作记录操作者、时间、依据和前后金额。
- **[medium] “可信”缺少可被反驳的指标**（addendum.md:16-20）— 文档把实名、资质、状态同步和记录列为启示，却没有衡量安全、履约、通知或投诉的标准。Fix：补充履约率、异常升级及时率、记录访问审计覆盖率、退款时限、投诉/事故率和优惠券成本等成功与反指标。
